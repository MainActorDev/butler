## Goal and context

The fix agreed in conversation: keep Butler un-integrated from Lionidas for now, but give the demo a **small, real-feeling domain** where the agent's output is something a person would actually want done — so the gates (budgets, policy, validator-as-truth, memory) land emotionally, not just technically.

- Operator: a different demo use case "feels right"; Lionidas integration explicitly NOT yet.

## Exploration — candidate domains

Criteria: (a) the job is instantly understandable to a developer watching; (b) the output is inspectable (a table, a file, a diff — not prose); (c) it exercises read → draft → validate → human-publish naturally; (d) it works on fixtures, no external services; (e) it makes the POLICY gate obviously correct ("you'd never want the agent to auto-do X").

| # | Domain | The agent does | Why it lands | Risk |
|---|---|---|---|---|
| 1 | **Changelog drafter** | reads a folder of git-like commit/diff fixtures + a version number → drafts CHANGELOG.md entries (categorized: feat/fix/breaking) → validates against a changelog schema (every entry cites a commit sha) → saves a draft changelog; **publishing to the repo is act-class = refused** | Every dev has written changelogs they hated writing. Diff chunks + symbol chunks are ALREADY in butler. Provenance (entry → commit sha) is the whole point. The refusal is obviously right: no agent should commit. | Low |
| 2 | Inbox triage → task table | reads fixture emails → drafts task rows (title/priority/owner) → validates schema → inserts into a real SQLite tasks table; **deleting/assigning to humans is act-class** | The output is a table you can look at — very legible. "Never auto-assign work to a human" is a visceral policy win. | Feels like a CRUD app; less agentic |
| 3 | Incident postmortem scribe | reads fixture log excerpts + timeline → drafts a postmortem doc (timeline, contributing factors, action items) → schema-validates → refuses to file Jira tickets | Emotionally real for anyone who's been paged. | Log fixtures are synthetic-looking; harder to make believable |
| 4 | Release-notes → QA checklist | reads a changelog fixture → drafts a manual QA checklist per change → validates each item references a change → refuses to mark items "passed" | Directly adjacent to Lionidas (same muscle, different repo) — good foreshadowing. | Half-way to Lionidas; may feel like a placeholder |
| 5 | Docs gap finder | reads a code repo (the symbols work!) + existing docs fixtures → drafts "documented vs actual" gap report → validates claims cite code symbols → refuses to edit docs | Shows off repo ingestion + symbol chunks — the newest machinery. | Output is a report (prose-ish); less "did work for me" |

**Proposal (unaccepted): #1 Changelog drafter**, with #2's table-legibility trick borrowed for the UI (entries render as a categorized list).

Why #1 wins on the criteria:
- **Instantly understood:** everyone hates writing changelogs; nobody needs the concept explained.
- **Inspectable output:** a markdown file with categorized entries — diffable, reviewable.
- **Natural pipeline:** commits/diffs are SOURCE documents (the ingest + chunk machinery, incl. diff chunking and symbol chunks, gets exercised for real); the changelog is the DRAFT; the schema validator (every entry must cite a commit sha that exists in the corpus) is ground truth; **git commit/push is the act-class refusal** — the purest possible "human presses publish".
- **Provenance sings:** each entry carries the sha it came from — the same discipline that will gate Lionidas case citations.
- **Fixtures only:** a `demo/fixtures/repo/` with ~15 real-looking commits (diffs touching the symbol-scannable TS files) — no network, hermetic.
- **Foreshadows Lionidas structurally** without touching it: source → draft → validate → refuse-publish is exactly the Jira→case-YAML shape.

Demo shape: same Vue UI + conversation API + WS feed; the "spec.draft/validate" tools become `changelog.draft/validate`; documents browser shows commits + diffs; notes browser collects learned conventions ("BREAKING changes must mention migration"); the refused act tool is `changelog.publish` (would run `git tag + commit` — refused under draft policy).
